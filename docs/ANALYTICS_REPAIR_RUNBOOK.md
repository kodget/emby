# Analytics repair — item 14 in progress

## Verified report repair, 2026-10-20

The main `/analytics` report now builds a single evidence set and a single local calendar window for its headline totals, trend, daily activity, consistency, assessment-type breakdown and topic detail. A seven-day window contains today and the previous six local dates. Future events are excluded, and every component uses the same cutoff. Study-only activity displays a report instead of an empty state. Short sessions are summed in seconds before display rounding.

Versioned, submitted `QuizAttempt` records supply their own evidence even if the corresponding completion event is missing or duplicated. Correct MCQs are recalculated from the saved question keys and selected answers, including unanswered items in the denominator; stale cached counters cannot inflate these report figures. Open attempts and historical assessments without saved versions do not contribute scores. The report explains the excluded historical count and the number awaiting written grading. Written marks remain in assessment results rather than being mixed into objective-item accuracy. Self-rated flashcard outcomes do not inflate objective accuracy.

Other activity uses valid persisted counts and nonnegative duration, with known one-time completion resources deduplicated by activity/type/id. Repeat reading activity remains separate. These read-side safeguards do not rewrite the ledger, issue rewards, or repair every upstream writer. Durations are recorded elapsed time, not proof of attention.

Streaks and active days are derived in local date order from the accepted evidence, instead of stale `UserStats` or rounded daily-session caches. The report's streak can therefore differ from other app surfaces until the remaining reconciliation work is finished. Trends require ten scored objective items in each half-window and use weighted counts; the report warns that different question sets affect comparisons.

Topic detail uses the selected period's evidence, not the lifetime `WeakArea` cache. It uses current authorized curriculum labels or original mock coverage labels, preserves course/module/submodule/topic scope distinctions, requires at least three items, and separates areas below 75% from those at or above it. These are descriptive report thresholds, not new achievement criteria or predictions of mastery. The page labels the figures as observed accuracy.

The browser cancels stale request updates when switching periods; an older seven-day response cannot replace the selected ninety-day report. Zero accuracy renders zero bar width. Existing premium topic-detail policy is retained.

Cache-only daily rows are retained with proposed zero counters, and the old numbers remain in the receipt; they are not converted into fabricated activity.

The command does not alter learning events, attempts, answers, source files, XP awards, points, rank, credit balances, question exposure or achievements. It does not prove that missing historical activity was never performed and does not repair deleted source evidence. Review cache-only discrepancies accordingly. Receipts preserve old numeric values for inspection; there is no automatic undo/re-award command. Production application still requires an explicit reviewed backup/staging process and has not occurred in this task.

After an account opts into reconciliation, subsequent activity recomputes its total minutes and the affected day's counters from accepted seconds, using the evidence already loaded for streaks. This prevents legacy rounding or invalid raw events from reintroducing drift, including fractional sessions on different days and zero-duration activity.
